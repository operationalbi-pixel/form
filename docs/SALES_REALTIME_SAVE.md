# Analisa Sales: direct autosave

The Sales Analysis page sends edited daily sales and analysis directly to the existing authenticated GAS save APIs. The same request writes and flushes Google Sheets before returning success. New saves never use `queueSalesSave`, job records, background processing, or status polling. This change retains Google Sheets as the database; it does not migrate Sales data to D1.

Typing pauses of 800 ms trigger autosave. Blur and the existing Save/Submit controls flush immediately. Each record has one mutable draft and at most one request in flight: further edits replace the draft, and only the latest remaining fields are sent after the response. An acknowledgement updates the calendar, totals, right panel and HQ sales modal locally, without waiting for a dashboard reload. It cannot clear newer input or apply an older refresh over confirmed values. Short analyses are saved as pending until the existing minimum length is met.

The page distinguishes unsaved, saving, saved and failed input with plain inline text beside the editors. There is no floating save notification box or save-failure toast. Drafts are backed up per authenticated employee and are restored after reload or a new login. Restored drafts require user review/Save; temporary failures are retried at most three times in the same direct save operation, repeating the same sent payload and optimistic field baselines before sending a newer draft. Offline edits are backed up and resume on reconnection in the current page. Reloaded drafts still require review/Save. A blank sales field is retained as a draft; zero must be entered explicitly. Each edited field carries its last confirmed value. The Sheet writer checks that baseline under the existing writer lock: an already matching value confirms a lost acknowledgement without another daily write; a conflicting newer value is preserved and the draft remains available for review. Acknowledgements rebase the next latest edit. Daily, weekly and monthly writes are guarded; old unguarded clients must reload. Conflict refresh preserves the visible draft, and an explicit Save reviews its baseline. Save requests time out after 30 seconds instead of five minutes; only transient guarded writes retry, with two bounded backoff delays. Authorization, validation and conflict errors never auto-retry. There is no guarantee of network availability or zero write latency.

The backend advertises direct-save version 2. Unguarded old clients must reload. `queueSalesSave` and `retrySalesSave` reject queued writes. After confirming all previously accepted Sales jobs COMPLETE on 27 October 2026, the legacy processor was retired and its trigger self-removes. Historical receipts are retained. Normal Sales writes no longer query D1 job history or invoke UrlFetch for a legacy fence; this prevents the exhausted Apps Script UrlFetch daily quota from blocking otherwise local Sheet saves. Explicit historical inspection can still require UrlFetch. Old browser inputs remain reviewable drafts, not automatically replayed jobs. Daily quota errors are permanent for that request and do not trigger bounded retries.

Validation covers direct acknowledgement and partial fields, typing during a save, stale dashboard responses, rapid edits, duplicate Save clicks, failures/reload, explicit zero, legacy fencing and rejection of new job acceptance. No fabricated production sales are submitted for verification.

Explicit Save and Enter wait for the revision visible at the click. If an earlier autosave is running, the latest draft is sent immediately after its acknowledgement, without the autosave debounce delay. Double clicks share the active write. Transient retries repeat the original absolute value and baseline so a lost acknowledgement can be confirmed idempotently before a newer edit is sent. Sales-only Save includes daily analysis only when it has an unsaved draft. Confirmations update the displayed monthly totals and outlet ranking and invalidate copied Daily Reports containing MTD totals. “Tersimpan” still requires a successful Sheet acknowledgement; network and Apps Script execution time remain real.

Daily Report can be copied before every outlet has entered Sales, including a day with no reported amounts yet regardless of whether daily targets have been uploaded. Missing Sales entries and explicit zero are both displayed as `0`, and the usual total format is retained without an extra completeness note. Previous MTD sales remain included. The copy button prepares reports without checking aggregate Sales > 0; fetch failures stay retryable and are not labelled as missing Sales. Available daily targets are summed through the report date; a mid-month opening or reopening does not require targets for earlier closed days. Where some targets exist, existing target-based outlet selection is retained. If no outlet has targets through the selected date, the report includes all active outlets with zero target values. Reports accept any valid selected date, including today and future dates, without an H-1 cutoff.
